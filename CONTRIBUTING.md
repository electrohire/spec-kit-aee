# Contributing

Contributions are welcome through issues and pull requests.

1. Preserve the Evaluator Contract distinctions among observed, inferred, asserted, contradicted, and unsupported evidence.
2. Add deterministic tests for every new challenge, output, or path-handling behavior.
3. Keep domain logic in `applied-epistemic-engineering`; keep this repository a thin Spec Kit adapter.
4. Run `pytest -q` and validate `extension.yml` before opening a pull request.
5. Do not commit generated assessment data, credentials, or private evidence.

By contributing, you agree that your contribution is licensed under the MIT License.
